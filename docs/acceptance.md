# v0.1の実配信受け入れ

## 機能の確認

1. 有効なYouTube APIキーと、チャットが有効な日本語ライブのURLを入力する。
2. 接続以前の過去コメントが流れず、新着のみに`comment_received`が記録されること。
3. 普通の質問、事業批判、冗談、挨拶、人格攻撃を含む合成コメントを人がテスト配信へ投稿する。Pluginには投稿機能を設けない。
4. 攻撃をhide、批判をshow、lowを非表示、highを★として表示すること。これは統計的精度の証明とは別。
5. 3秒固定と新着highの先頭追加、最大10件、👍と×、再接続時の古い結果の破棄を確認する。
6. ネットワークを切断し、状態表示と回復を確認。OBS録画・配信のフレーム落ちを通常時と比較する。自動BAN・返信・Overlayは存在しないこと。
7. ログ本文・キー不在、ローテーション、表示までのlatencyを確認する。

## 評価指標

専用テスト配信または同意のある評価データを用い、普段の本文非保存運用と分離する。隠したコメントを運用Dockへ戻さず、評価担当者が別の手元のデータで正解ラベルをつける。

- Hide Precision = `hideされたうち配信者が隠したいとラベル付けした件数 / hide件数`。分母0は未定義。通常の批判を隠した件数も別に報告。
- Recommendation Precision@10 = `上位10件のうち拾ってよいと明示評価された件数 / 評価した上位10件数`。未反応を否定評価と推定しない。top4も別集計。
- Discovery Improvement = 同じコメント集合・同じ制限時間について、生コメント欄と推薦Dockで発見できた「拾いたいコメント」の割合を比較する。順番をランダム化し、同一参加者の記憶効果を抑える。絶対差（percentage points）と相対改善を区別。
- Latency = `comment_shown.latency_ms` のp50/p95、標本数。YouTube受信前の`youtube_delivery_ms`は別表。過負荷破棄率と非表示率も同時に報告する。

実配信から最低数百件以上を評価し、母数・不確実性・コメント量を併記する。4件の合成データ成功を精度100%やMVP受け入れ完了とは扱わない。
